# SlutSearch <3 — Telegram Mini App MVP

Рабочий начальный проект Telegram-бота + Mini App. Интерфейс построен по композиции предоставленных референсов: верхнее меню, поиск, теги, фильтры, сетка публикаций, аватар пользователя, плейлисты и закладки. Палитра SlutSearch: очень тёмный фон + холодный электрический синий. **Нет сторонних npm-зависимостей.**

## Что уже работает

| Экран / система | Что реализовано |
|---|---|
| Home | поиск по 1–5 тегам с логикой AND; подсказки популярных тегов; счётчик; список публикаций |
| Filters | изображения / видео; последние, старые, по лайкам, просмотрам, случайно; сетка / Masonry; скрытие AI |
| Hot | подборка контента с сортировкой по просмотрам, лайкам или дате |
| Profile | фото/имя Telegram; вкладки My uploads, Bookmarks, Playlists; статистика |
| Playlists | создание, просмотр, добавление/удаление публикаций, удаление списка |
| Upload | картинки JPG/PNG/WEBP/GIF и видео MP4/WEBM/MOV; обязательные 1–12 тегов; отметка AI; подтверждение согласия и прав |
| Социальные функции | лайки, закладки, просмотры, жалобы |
| Модерация | новые публикации ожидают одобрения; admin API + простая админ-панель в Settings профиля |
| Telegram bot | ответ на `/start` и `/help` кнопкой открытия Mini App; вход по подтверждённому initData |
| 18+ | экран подтверждения возраста для прототипа; реальная обязательная проверка возраста перед публичным запуском пока не реализована |

## Запуск локально

Требуется **Node.js 22 или новее**.

```bash
cd slutsearch-telegram-mvp
npm run dev
```

Откройте `http://localhost:3000`. Локальный режим автоматически использует тестового пользователя, а загрузки видны сразу без модерации. Он **только для разработки**.

Обычный запуск без тестовой авторизации:

```bash
npm start
```

После обычного запуска сайт попросит открыть приложение через Telegram. Без `BOT_TOKEN` и подтверждённого `initData` вход не пройдёт.

## Подключение бота Telegram

1. В Telegram откройте **@BotFather**, создайте бота через `/newbot` и сохраните токен.
2. Разверните проект на своём сервере Node.js 22 с **публичным HTTPS-адресом**. Нужны постоянное хранение файлов, HTTPS-сертификат и домен.
3. Настройте переменные окружения из `.env.example`: `BOT_TOKEN`, `WEBAPP_URL`, `BOT_USERNAME`, `ADMIN_TG_IDS`.
4. Запустите `node --env-file=.env server.js` (Node 22) или передайте переменные средствами хостинга.
5. Откройте своего бота, отправьте `/start` и нажмите **Открыть SlutSearch**.
6. Дополнительно через BotFather `/setmenubutton` задайте ссылку на `WEBAPP_URL`, чтобы Mini App открывался из постоянной кнопки меню бота.

**Не публикуйте токен бота и .env в GitHub.** HTTPS обязателен для рабочего Telegram Web App.

## Поиск и теги

- Поиск: от 1 до **5** тегов. Публикация должна содержать **каждый** выбранный тег (AND).
- Загрузка: **1–12** тегов, через запятую. Пример: `digital art, blue hair, portrait`.
- Теги приводятся к нижнему регистру, пробелы нормализуются. Клик на популярный тег добавляет его в поиск.
- Сортировка `Top rated` использует количество лайков, `Most viewed` — количество просмотров.

## Модерация

В обычном режиме все медиа получают статус `pending`. Модератору нужно добавить свой **цифровой Telegram ID** в `ADMIN_TG_IDS` (через запятую для нескольких). Затем открыть свой профиль и нажать `Settings`, чтобы увидеть очередь на одобрение. Репорты регистрируются на сервере и видны числом; расширенный интерфейс обработки жалоб — дальнейшая задача.

Публикации нельзя считать публично опубликованными до решения модерации. В тестовом режиме `npm run dev` автоодобрение включено специально для локального просмотра.

## Проверка

```bash
npm run check
node --test tests/smoke.mjs
```

Интеграционный тест запускает изолированный сервер и проверяет проверку подписи Telegram, авторизацию, загрузку файла, поиск, модерацию, лайки, закладки, плейлисты и жалобы. Он использует временную папку и не портит пользовательскую базу.

## Важно перед настоящим запуском

Это **функциональный MVP и стартовый код**, а не готовая к публичному запуску платформа с пользовательским 18+ контентом. Ознакомьтесь с `SECURITY.md`. Необходимо внедрить эффективную проверку возраста по применимому законодательству, проверку права на загрузку материалов, зрелую модерацию, процедуру блокировки/удаления незаконного контента, защиту медиа, антивирусную проверку, резервное копирование и объектное хранилище (например, совместимое с S3), а также заменить файловый JSON на транзакционную базу данных.
